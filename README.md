# MusicHub

**多音源音乐聚合播放与下载器** · 桌面端（Electron + Vue 3 + TypeScript）

搜得到、接得上、放得出 —— 一个把「聚合搜索 + 第三方音源 + 本地代理」三件事做完整的桌面音乐工具。

> 本软件不存储、不提供任何音乐内容，只作为聚合播放工具，
> 通过用户自行导入的第三方音源脚本获取播放地址。请勿用于商业传播。

**下载**：[最新版本](https://github.com/123maizi/musichub/releases/latest) · Windows x64

## 特色一览

| 特色 | 说明 |
|---|---|
| **五大平台内置搜索** | 酷我 / 酷狗 / QQ / 网易云 / 咪咕 并发搜索，结果归一到统一结构 |
| **洛雪（LX）音源协议完整实现** | 第三方音源脚本即插即用，宿主负责协议握手、能力上报、取流调度 |
| **vm 沙箱运行第三方脚本** | 独立上下文、`require` 白名单、定时器可回收、console 输出可视化 |
| **本地流代理** | 平台媒体地址普遍校验 Referer/UA，代理补头并解决跨域，`<audio>` 才能播 |
| **音源自适应择优** | 按历史成功率打分，音质从高到低分层，层内并发竞速，失败自动降级 |
| **播放与下载同一条取流路径** | 能播的就能下，行为一致，不存在「播放能行下载不行」 |
| **断点续传 + 标签写入** | `.part` 续传；手写 ID3v2.3 / FLAC Vorbis Comment，含封面与歌词 |
| **歌词 + 翻译** | 多源回退取词，逐行对照；翻译支持本地/公开/自建接口 |
| **零依赖标签实现** | 不引第三方音乐库，自己按规范写字节，避免依赖腐化 |
| **不编造数据** | 拿不到就显示 `--:--` 或空态提示，绝不填占位假值 |

## 功能特性

### 搜索

- 五大平台**并发搜索**，结果按平台分组展示，可切换「全部 / 单平台」
- 搜索页**空态即推荐位**：没搜索时显示歌曲列表（默认**继续听**＝历史播放），
  可在设置里切换为 **我的喜欢 / 歌单歌曲**
- **历史搜索记录**：最多 20 条、去重、最新在前；点选即搜、单条删除、清空全部；
  键盘 `↑` `↓` `Enter` `Esc` 全可用
- 搜索历史**只在真正发起搜索时记录**，不是每敲一个字都记
- 结果表格支持多选、批量下载、收藏、加入歌单、加入队列、跳转专辑/艺人

### 播放

- 底部播放条 + 正在播放页（大封面、逐行歌词、可编辑译文）
- **进度条位置来源唯一**：拖动/点击落点与鼠标一致（误差 ≤2px、零回弹帧）
- **换歌进度归零**、单曲循环、随机、上一首/下一首、音量
- **键盘步进**：方向键每次正好 ±5 秒
- 进度**只增不减**（同一首歌内），避免时长从元数据切换成流真实时长时跳变
- 音源被判为试听片段时**换源但保位置**，绝不打回起点

### 下载

- 队列 + 并发 + 重试 + **断点续传**（任务级 `.part`，换源不续传旧残留）
- 下载格式可选，**MP3 320Kbps / 128Kbps / FLAC 无损 / FLAC 24bit 母带**
- 落盘后写入标签（标题/歌手/专辑/封面/歌词），**MP3 与 FLAC 在 Windows 播放器可直接打开**
- 任务行显示真实容器与格式是否匹配，缺失文件有标记并可重新下载

### 音源

- 三种导入方式：**从文件 / 从 URL / 一键导入内置音源**
- 音源页可启停、查看能力（支持平台、最高音质）、看诊断日志
- **音源能力校正**：搜索结果里不能播的音质会被标注出来，不给你假选项

### 界面

- **大理石与墨**：暖白画布、墨色文字、**氧化青铜**单强调色、**零圆角零阴影**（层次只用 1px 刻线）
- 碑刻衬线标题 + 大留白内容墙，**极窄图标柱 + 通高刻线**的陈列馆式骨架
- 过渡动画克制（240/360/520ms，重物落定手感），**尊重系统「减少动效」设置**
- 全站设计审计可量化：对比度 0/1029 不达标、离网间距 0、命中区 <24px 为 0

│  │  · SourceSandbox   vm 沙箱执行第三方脚本                │ │

### 它解决什么问题

市面上的音乐聚合工具，核心难点从来不是「播放器」，而是这三件事：

1. **搜得到** —— 洛雪（lx-music）音源协议只提供「取流」，**不提供搜索**。
   想要搜歌，宿主必须自己实现各平台的搜索接口。
2. **接得上** —— 音源脚本是第三方 JS，格式不一、有混淆、有版本要求，
   需要一个能安全隔离、可诊断的运行时。
3. **放得出** —— 平台返回的媒体地址普遍校验 Referer / UA，直接丢给 `<audio>` 会 403，
   需要一个本地代理来补头并绕开跨域。

MusicHub 就是围绕这三点设计的。

### 两条数据链

**搜索链**（自建）
```
关键词 → SearchEngine → 5 个平台 Provider 并发 → 归一化 Song[]
                    ↗ 另可选：音源脚本自带 musicSearch
```

**播放/下载链**（复用同一套取流逻辑）
```
Song → MusicResolver → 按平台挑音源 → LxRuntime.dispatch('musicUrl')
                    → 拿到裸地址 → StreamProxy 包装成本地地址
                    → <audio> 播放 / DownloadManager 落盘
```

播放和下载走**同一条取流路径**，所以「能播的就能下，播不了的也下不了」，行为一致。

### 音源协议（洛雪 LX 格式）

音源脚本开头的固定写法：

```js
const { EVENT_NAMES, request, on, send, utils, env, version } = globalThis.lx
```

宿主需要做的事：

1. 在脚本执行前把 `lx` 注入其上下文（`vm.createContext`）
2. 接收脚本的 `send(EVENT_NAMES.inited, { status, sources })` —— 这就是能力上报
3. 需要取流时，调用脚本通过 `on(EVENT_NAMES.request, handler)` 注册的处理器，
   传入 `{ action: 'musicUrl', source: 'kw', info: { type: '320k', musicInfo } }`

`action` 取值：`musicUrl` | `lyric` | `pic` | `musicSearch`

### 沙箱

- 独立 `vm` 上下文，脚本的 `globalThis` 被替换
- `require` 走白名单（crypto / buffer / url / … ，**不含** fs / child_process / net）
- 定时器可跟踪可回收，防止脚本泄漏
- `console` 输出被捕获，在音源详情里可视化，音源报错能直接看到上下文

> `vm` 不是安全边界，它的目标是「隔离全局、限制能力、可回收」。
> 音源脚本始终来自第三方，请不要导入来路不明的脚本。

### 音源未知性的处理

音源会失效、会限流、会互相冲突。所以取流不是「选一个源试试」，而是：

1. 按**历史成功率**给音源打分排序
2. 音质**从高到低**分层（无损 → 320k → 128k），层内 **3 个并发竞速**
3. 拿不到就自动降级，最后能听到歌永远优先于听到最好的音质
4. 每次结果回写统计，**越用越准**

### 本地流代理

平台 CDN 普遍带防盗链，`<audio src="远程地址">` 会 403。做法是：

- 起一个本地 HTTP 服务，把远程地址包成 `http://127.0.0.1:<port>/stream?u=<b64url>&r=<referer>`
- 代理按 `r` 参数补 `Referer` / `User-Agent`，**透传 Range**（拖动进度条靠它）
- 本地文件另走 `/local?p=<b64url>`，且**只允许在已知目录白名单内**取值
- 退出时跟踪的连接全部销毁、在途请求全部 abort、`closeAllConnections`

### 标签写入

不引第三方库，直接按规范写字节：

- **MP3**：ID3v2.3，帧长用 synchsafe 编码；`TIT2/TPE1/TALB/APIC/COMM`
- **FLAC**：Vorbis Comment block，其余 block 原样保留
- 写完**必须用系统解码器验证** —— Chromium 宽容，能播不代表别的播放器能播

### 三个「会伪装成缺陷」的坑（都踩过，已加防护）

1. **隐藏窗口里 `requestAnimationFrame` 完全停摆**
   被遮挡的窗口会被 Windows 判定为后台，rAF 一帧不跑（实测 600ms 内 0 帧）。
   所有逐帧测量的指标会全部失真，Vue 的过渡动画还会因此卡死界面。
   → 路由入场改成**纯 CSS 动画**（不依赖 rAF），探针一律先做环境守卫。
2. **`position: fixed` 被带 `transform` 的祖先劫持**
   CSS 规定带 transform 的祖先会成为 fixed 子元素的包含块。
   路由动画的 keyframe 里带 `translate3d` 且 `fill-mode: both`，会让内容容器**永久**成为包含块。
   → 浮层一律 `Teleport` 到 `body`。
3. **构建产物与源码不一致**
   在队友构建的瞬间启动应用，会拿到半新半旧的产物，报出像代码写错的错误。
   → 所有验收脚本输出头必须带**构建标识**（入口 chunk 名 / mtime），先自证测的是哪个构建。

## 版本更新史

### 🔴 革命性更新

#### v1.1.0 — 全面优化：更快、更省、更不容易出岔子

一次把整套东西从里到外过了一遍，**所有结论都以实测数字为准**。

| 指标 | 之前 | 之后 |
|---|---|---|
| 启动到能搜歌 | 15 秒 | **2 秒** |
| 音源装载总时长 | 30.2 秒 | **16.2 秒** |
| 产物体积 | 875 KB | **395 KB（−53.6%）** |
| 长列表首次挂载长任务 | 108 ms | **0** |
| 勾选一行的响应 | 5.3 ms | **1.0 ms（约 5 倍）** |
| 24 并发搜索的上游请求 | 120 个 | **5 个（−96%）** |

- **音源装载并行化**：原来 27 个脚本串行，2 个慢脚本堵住全部；现在并发 5，健康的 24 个 2 秒内可用
- **搜索请求风暴**：缓存只存「已完成」、无进行中去重 → 24 并发打 120 次平台。加在途去重 + 平台熔断
- **根治进度条偶尔回退**：判据过松把完整音源误判成试听片段并重播整首。改为换源不重播、seek 回原位
- **封面覆盖率 95.7% → 100%**：真正瓶颈是「只看分数最高的一个候选」+ 失败结果被永久缓存
- **孤儿进程治理**：沙箱定时器句柄泄漏、隐形窗口（进程活着界面永不出现）全部封死
- **开启构建压缩**：electron-vite 默认不压缩，打开后体积直接腰斩

#### v1.2.0 — 界面全面重做：大理石与墨

从「深色仪表盘」换成**欧洲古典**质感，功能一个没少。

### 🔵 修复版本

#### v1.3.3 — 换歌时进度条归零

换歌复用了 `bumpProgress(force)`，而 `force` 的语义是「回退到按当前状态算出的值」——
那个值拿**尚未重置的 `currentTime`**（上一首播到的秒数）除以**新歌时长**，于是进度条停在旧百分比上。
改为换歌处显式清零。实测切歌后 250/500/750/1000ms 的进度为 **0 / 0.1 / 0.2 / 0.3**。

#### v1.3.2 — 修搜索历史下拉弹出的位置

下拉应紧贴输入框正下方，实际右移 105px、下移 72px。
根因是 `position: fixed` 被带 `transform` 的祖先劫持（偏移量恰好等于容器的视口偏移）。
改用 `Teleport` 到 `body` 后，左边缘偏差 **0**、宽度一致。

#### v1.3.1 — 修复搜索历史下拉的两个 bug

- **下拉不出现/列表为空**：搜索页挂载即自动聚焦输入框，导致下拉组件挂载时 `visible` 已是 `true`，
  `watch` 只在变化时触发 → 永远不读历史。改为挂载时无条件读一次 + 直接监听锚点自身
- **关闭不生效（幽灵浮层）**：状态已关闭但浮层留在 DOM 里，点外关闭与 Esc 都关不掉，
  等于一个盖住页面的浮层。根因是 `<Transition>` 的离开过渡没摘元素 → 改为一次性 CSS 动画

#### v1.0.10 / v1.0.11 — 修「下载的 MP3 在系统播放器里打不开」

浏览器能播、Windows 播放器报 `0xC00D3E8C`。定位到 ID3 注释帧（COMM）写错了：
描述终止符在 UTF-16 编码下需要 **2 字节** `00 00`，代码里写了 1 字节，整个注释体错位一字节，
Media Foundation 因此拒绝整个文件。修完并回修了已下载的那几个文件。
**教训：Chromium 宽容会掩盖格式错误，必须用系统解码器验证。**

#### v1.0.4 – v1.0.9 — 早期版本

下载格式选择（MP3/FLAC 四档）、歌词与翻译、歌单与收藏、专辑/艺人页、音源导入与管理等基础能力。

### 诊断脚本

音源接口和搜索接口都会不定期失效。这些脚本是判断「哪条路还通」的最快手段：

```bash
node scripts/probe-search.mjs 周杰伦      # 探五大平台搜索接口
node scripts/probe-alt.mjs 周杰伦         # 探备选接口
node scripts/dump-one.mjs 周杰伦          # 转储原始响应字段结构
```

验证真实的归一化映射（走真实代码路径）：

```bash
node_modules\.bin\esbuild.cmd scripts/verify-search.ts --bundle --format=esm \
  --platform=node --outfile=.tmp/verify-search.mjs --alias:@shared=./src/shared
node .tmp/verify-search.mjs 周杰伦
```

### 验收与性能基准

```bash
node scripts/acceptance.mjs <端口>        # 11 项端到端功能验收
node scripts/design-audit.mjs <端口>      # 设计审计（对比度/间距/命中区/动效）
node scripts/perf-bench-140.mjs <端口>    # 140 行长列表性能基准
```

跑探针前建议先确认环境可信（隐藏窗口里 rAF 停摆会让数据全部失真）：

```powershell
# 启动时关掉 Windows 原生遮挡检测，避免窗口被误判为后台
electron . --disable-features=CalculateNativeWinOcclusion
```

## 音源导入

支持三种方式（音源页）：

- **从文件导入** —— 选择本地 `.js` 音源脚本
- **从 URL 导入** —— 粘贴直链
- **导入内置音源** —— 一键装入 `resources/sources/` 下的随附音源

音源存放在用户数据目录下的 `sources/`，可用「打开目录」直接管理。

## 已知限制

- 咪咕搜索结果不返回时长，列表中显示为 `--:--`（不编造数据）
- 标签写入支持 MP3 / FLAC；M4A 的 MP4 atom 改写风险高，暂未实现
- 网易云对部分歌手只有翻唱版本 —— 歌词匹配要求**歌名与歌手同时对上**，
  宁可显示「没有歌词」也不挂别人的歌词
- 第三方音源随时可能失效，这是生态常态，不是软件缺陷
