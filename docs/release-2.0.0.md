# MusicHub 2.0.0

**一次把播放内核、音源体系、进度条、歌词翻译全部重做的大版本。**

从 1.x 一路修到 2.0：这一版不是加功能，而是把几件一直「能凑合用」的事真正做对——
播放不再找不到音源、进度条不再和鼠标错位、歌词译文不再只显示一半、
并且把这些改动全部建立在实测数据之上。

---

## 一、播放内核：从「能播就行」到「不会听不了」

### 1. 彻底解决「找不到音源」

- **装载期不再误判**：刚启动十几秒里多数音源还没握手完，此时挑不出候选是**正常中间状态**。
  现在会等待（≤5 秒），而不是立刻报「找不到音源」。
- **冷却不再是「听不了」的理由**：候选少于 3 个时无视冷却；仍失败还有「最后一搏」——
  把该平台**全部**音源（含冷却中的）再完整跑一遍。
  > 只要系统里还存在任何一个支持该平台的音源，就一定会去试。
- **同一次解析只跑一趟**：点击时若解析已在跑，直接搭车（in-flight 去重）。
- **静默换源**：切换音源全程不留红色提示，彻底失败才给一次明确说明。

### 2. 不再出现「报错了、过一会儿又自己唱起来」

`Promise.race` 的失败者不会被取消 —— 超时的 `play()` 可能在几分钟后突然成功并出声。
现在有 `loadAttemptSeq` 迟到成功守卫，并且终态失败会显式 `pause()`。

### 3. 音源体系：27 → 46 个，全部通过纯净性审计

新增 19 个音源（去重后），**逐个审计过域名**：全部只声明 163 / QQ / KW / KG / MG，
**零视频平台接口**（没有 B 站、YouTube 这类）。实测 46/46 可用。

## 二、进度条：逐像素精确、永不卡住

两条进度条（底部缩略条 + 正在播放页大图条）合并成**一份实现**
（`composables/useSeekBar.ts`）——它们原本各写一套，然后各自演化出不同的毛病。

| 指标 | 修复前 | 2.0.0 |
|---|---|---|
| 点击落点误差 | 最多 **−2.5 秒**（`step` 量化：1320px 轨道上 12px） | **≤ 0.2 秒** |
| 拖动中「填充 vs 指针」偏差 | 量化 + 520ms 缓动拖尾 | **0.00%（0px）** |
| 拖动工况矩阵（7 种甩/拖/松手方式） | **7 个里 3 个被吞** | **7/7 生效** |

两个根因都不是手感问题，而是缺陷：

1. **Chromium 的原生 range 会漏发 `change`**。事件取证（真实鼠标）显示，同样的快速甩动，
   成功那次有 `change`、失败那次 `pointerdown → input×3 → pointerup → mouseup → click`
   全到、**只有 `change` 没来**。而提交、`seeking` 释放、`seek()` 全挂在 `change` 上，
   于是漏发时：条子被钉在拖动值上不动、音频停在原处、2 秒看门狗再把整段拖动丢掉。
   现在 `pointerup` / `lostpointercapture` / `pointercancel` / 窗口级 `pointerup`
   任一到达即提交，另加「拖动静默 320ms」兜底。
2. **落点被 `step` 量化**。`step` 又不能改小（实测会让指针命中整体坏掉），
   所以改成由指针像素反算落点，`step` 只服务键盘。

## 三、歌词与译文：零 AI，也要「几乎全有中文」

### 1. 跨平台时间戳偏移（这才是「只显示一半」的真凶）

主歌词与译文常来自不同平台，两条时间轴**不一致**。实测 Ex-Factor：
主歌词 88 行、网易云译文 65 行、**偏移中位数 0.74 秒** —— 旧的固定 0.5 秒最近邻
只配上 **15 行**。现在先估系统性偏移、再做**两指针单调对齐**（行序一致，
结构上排除乱配），实测 **15 → 63 行**；本来就对齐的版本 65/65 无回归；
**无关歌词仍然 0 行**（绝不硬塞）。

### 2. credits 不再混在歌词里（观感的决定性一步）

歌词面板顶部那串「作词/作曲/编曲/制作人/和声/吉他」本来就没有中文可翻，
却和歌词排在一起 —— 这才是「一半有中文一半没有」的主要来源。
现在它们从歌词流**分离**，在顶部单独一小块展示（信息不丢）。

| 曲目 | 歌词流行数 | 其中没译文 | credits 残留 |
|---|---|---|---|
| Shape of You | 135 → **104** | 50 → **19** | 24 → **0** |
| Blinding Lights | 38 → **35** | 8 → **5** | 3 → **0** |

### 3. 原文歌词先出，不再让人干等

原来是「音源链逐个试 → 再内置链 → 内置里 QQ 再网易云」四段**串行**，
最坏 **13.2 秒**才出现第一行歌词。现在两条链并发、内置两源也并发（非空才算赢）。

**第一行歌词出现：中位数 2143ms → 770ms；最坏 3209ms → 1395ms。**

### 4. 实测数据支持「零 AI」

平台现成译文对**真正的歌词行**覆盖 96~100%（Lemon 100%、残酷な天使のテーゼ 96.1%、
Dynamite 92.5%）。所谓「缺口」几乎全是 credits 与拟声行。
因此 **AI 自动补齐已下线**（接口保留，不自动跑）—— 不再有网络请求、不确定性与成本。

### 5. 多平台译文选项，按覆盖率设门槛

逐首收集 QQ / 网易云的现成译文，量「能对上主歌词多少行」：0 行的不显示，
按覆盖率排序并自动应用**最好的那份**；并且**不许把已有译文换差**。

## 六、本版边界（说清楚，不吹）

- 本版把「看起来缺一半译文」解决到**真歌词行基本全覆盖**；
  `Yeah` / `Hey, hey, hey` / `Oh—i—oh—i` 这类拟声行仍会留在歌词流里且没有译文。
- **多平台译文并集没有做**：收益上限只有一两行真歌词，而各平台**分行方式不一致**时
  并集会把译文与原文错位 —— 那比没有译文更糟。若将来发现某类歌缺口确实大，
  第一件事是补测「分行一致性」，而不是直接合并。
- 全功能验收 11/11 通过。
